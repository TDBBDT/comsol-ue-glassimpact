# 精度、数据容器与 UE 播放方案

## 物理数据不能全部使用 PNG8

| 格式 | 优势 | 限制 | 本版用途 |
|---|---|---|---|
| PNG8 | 通用、体积小、直观 | 仅 256 级，sRGB/压缩可能改变阈值；有符号位移易丢失 | 仅预览，不能反推物理真值 |
| PNG16 单通道 | 无损、65,536 级；工具普遍可读 | UE 导入格式/压缩需核对；多通道浮点支持差 | 可检查的 damage 辅助输出，关闭 sRGB |
| EXR half/float | 有符号浮点、多通道、适合场纹理 | 依赖额外编码库；UE 默认 HDR 压缩设置必须核查 | 后续离线纹理资产管线可采用 |
| NumPy NPY/NPZ | dtype/形状明确，科学处理方便 | UE 原生不读 NPY，需转换 | Python 诊断或研究中间件 |
| 原始 RGBA16F + JSON | UE `PF_FloatRGBA` 可直接上传；有符号/线性值不经过图片导入器 | 必须严格核验字节数、端序、范围与哈希 | 本版运行时主格式 |
| Float32 二进制 | 更高精度，适合审计与科学计算 | 两倍 half 大小；不是本版默认 GPU 格式 | 原始物理结果应保留 CSV/VTK 或求解器原文件 |

Half 在 [0,1] 内的间距不均匀，接近 1 时约为 0.000488；不能笼统声称 half 比 UINT16 更精确。损伤可受约数万分之几的编码误差影响；阈值应避开误差带，真实误差由输出的编码校验记录决定。位移按各分量的**全时程**仿射范围编码，所以实际米制误差与范围跨度有关。CSV 原始结果和元数据用于溯源，纹理用于显示。

损伤始终按绝对 0..1 存储，不把当前帧最大损伤强行变成 1。应力、能量、位移只建立一次全局最小值/最大值，所有帧复用。恒定通道编码为 0、解码为其真实常量。超出采样覆盖区域用 coverage 屏蔽，不由最近邻填补出不存在的裂纹。

## UE 容器选择

| 方案 | 适用场合 | 本项目判断 |
|---|---|---|
| 独立 Texture2D 序列 | 帧数很少、编辑器直接检查 | 32～64 帧×多个物理场导入和管理繁琐 |
| Texture2DArray | 全序列可驻留 GPU，Shader 自行选择层 | 性能好，但构建/导入与平台支持需验证，初版不选 |
| Volume Texture | 连续三维体数据 | 时间不是空间 Z；体纹理默认滤波语义易混淆，不选 |
| Render Target | 运行时累积、叠加、投影或 GPU 生成效果 | 本版播放离线固定场不必增加一次拷贝，可后续用于重复作用 |
| VAT | 稳定顶点编号的大规模网格动画 | 本版物理网格与渲染网格不同，UV 场更直接；拓扑变化不在范围 |
| 两帧瞬态 Texture2D | 已有二进制场，通过参数插值 | 本版选择；以真实时间寻找帧对，GPU 混合两帧 |

一套 CPU/材质时间参数同时驱动裂纹与位移，禁止每个通道各自累计时间。载入 metadata 后使用实际 `times_seconds`；支持非均匀时间步，不假设第 N 帧恒等于 N/FPS。

玻璃网格的局部 XY 对应 UV0；矩形面可以整体旋转立起来，但位移必须先从米转厘米，再从**局部向量**变换为世界向量。不能把局部法向位移直接写入世界 Z。UV 值、文件行号和预览图上方向之间的约定见 [数据映射](data_mapping.md)。

固定拓扑意味着裂纹表现主要来自材质，WPO 表达小幅变形；裂纹遮罩不会自动生成新的三角边界或碎块。法线扰动和折射变化是视觉参数，不能解释为已求解的真实裂缝开口或光学散射。
